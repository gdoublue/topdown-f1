AUTOPILOT · DRIVER ALGORITHM

自动驾驶算法 · 参数说明

在「选车面板 / 在线房间」打开 🤖 自动驾驶，把你的算法粘进编辑器即可接管自己的赛车。 单人计时、对战 AI、在线练习、在线房间全部通用。

入口函数 可读：car 可读：otherCars 车距与车身尺寸 可写：out 可读：赛道数据 工具函数 getApexReleaseCap 详解 跟车/超车返回值 坐标系与单位 物理边界 示例 注意事项

1. 入口函数：名字必须是 driver

编辑器里的代码会被当作一个函数体编译，最终取名为 driver 的函数： 

function driver(car, out, dt, otherCars) {
  // car: 你的车（只读）
  // out: 输出控制量（写入）
  // dt : 本帧物理步长（秒）
  // otherCars: 场上其他未完赛赛车（只读数组）
}

也可以写成 const driver = (car, out, dt, otherCars) => { ... }。 函数名不需要、也不应该叫 superDriver —— 内置算法默认也是用 const driver = ... 绑定的； 名字写错会在编辑器下方直接报错「没有找到 driver(...)」，不会静默回退。

想复用内置算法（例如只改一点点），可以在自己的 driver 里调用 superDriver(car, out, dt, otherCars)，然后再按需要覆盖 out 的字段。

四个参数速查

参数方向说明
car只读你自己的车：位置、朝向、速度、赛道索引等，明细见 第 2 节。
out可写本帧控制量：out.up / out.brake / out.steer，见 第 4 节。
dt只读本次物理步长（秒），通常 1/60 ~ 1/30；做积分/预测时用它换算。
otherCars只读场上车辆数组（包含你自己，只含未完赛车），每项结构与 car 相同，见 第 3 节。

运行机制（这几点最容易踩坑）

  • out 是每帧复用的同一个对象：out.up / out.brake / out.steer 每帧都必须显式赋值，不写就会沿用上一帧的值（例如提前 return 时刹车会一直踩着）。
  • 调用时机：每个物理子步调用一次。3 秒倒计时、弹窗打开（含参数说明/结算）、冲线之后都不调用。 弹窗打开期间比赛暂停，可以边跑边改代码。
  • 倍速快进会放大调用频率：按 + / - 切 2×~16× 时，一帧会切多个物理子步 （最多 32 步/帧），算法要够轻，别在里面做大数组分配或长循环。
  • 抛异常会中断该帧：异常会让这一帧剩下的物理与渲染全部跳过（画面像卡住）。有风险的除法、 数组越界用 try/catch 或条件判断挡住。
  • 输出 NaN 会毁掉车辆状态：out.steer = NaN 会让车坐标变 NaN，画面上直接消失。 算完用 Number.isFinite(v) ? v : 0 兜底。
  • 编译失败不会停车：状态栏显示 ✗ 时，车继续用上一次编译成功的算法； 从未成功过则退回该车内置 AI，而不是停在原地。
  • 代码自动保存：编辑器内容与开关状态存在浏览器本地（localStorage），刷新页面不丢； 「恢复默认 superDriver」按钮可一键还原。
  • 不要改 car / car.perf：它们是共享对象，改性能不会即时反映到弯速表缓存， 也会污染内置算法；在线成绩由服务器校验。

2. 可以读取：car（你的车，只读）

字段单位含义
car.x / car.y米世界坐标。原点在左上，y 轴向下。
car.angle弧度车头朝向。0 = 指向 +x；角度增大的方向在屏幕上是顺时针。
car.speedm/s有符号速度，倒车为负。×3.6 得 km/h。
car.steer-1~1当前（平滑后的）方向输入，可用于抑制抖动。

car.lap圈当前第几圈（从 1 开始）。

car.surf0 / 1 / 2当前路面：0 沥青、1 路肩（仅铺了路缘石的弯）、2 草地。

car.brakingbool上一步是否真的在减速（踩死刹车停稳后为 false）。
car.inBrake0 / 1 / 2上一步的刹车踏板输入：0 松开、1 轻刹、2 重刹（停稳也保留）。
car.inUpbool上一步是否踩油门。
car.inSteer-1 ~ 1上一步的方向输入，与车身横摆方向一致。
car.accelm/s²上一步的实际纵向加速度（负值 = 减速）。
car.best / car.last / car.total毫秒最快圈 / 上一圈 / 总用时（null = 还没有成绩）；car.lapTimes 是每圈数组。
car.gridPos / car.idx索引发车格位（0 = 杆位）/ 上一步的最近采样点下标（nearIdx 的历史值，可算横向移动量）。
car.id / car.name / car.color-车辆 id、全名、主题色，用于分支或调试打印。
car.perf-本车性能配置，见下表。
car.nickname / car.shortName / car.number-显示用信息。

字段含义
perf.maxSpeed[沥青, 路肩, 草地] 三档极速（m/s）。
perf.latGrip最大横向抓地（m/s²，÷9.81 得 G）。

3. 可以读取：otherCars（场上车辆，只读）

otherCars 是一个数组，每个元素都是一辆车的完整状态对象，字段结构与 car 完全相同 （x / y / angle / speed / nearIdx / trackS / raceDist / lap / finished / perf / nickname …）， 所以 第 2 节 的所有字段都能直接读。

注意：数组里包含你自己（与内置算法一致），判断"别人"要写成 for (const o of otherCars) { if (o === car) continue; ... }。

每辆车能读到的"肉眼可见"状态

字段单位说明
o.speedm/s有符号速度（倒车为负），×3.6 得 km/h。
o.angle弧度车头朝向。算相对方位：wrapAngle(Math.atan2(o.y - car.y, o.x - car.x) - car.angle)。
o.inBrake0 / 1 / 2刹车踏板：0 松开、1 轻刹（45%）、2 重刹。停稳后仍能看出他在踩着刹车。
o.inUpbool油门是否踩下。
o.inSteer-1 ~ 1方向输入，与车身横摆方向一致，可预判对方是进弯还是回正。
o.brakingbool是否真的在减速（物理结果，与 inBrake 互补）。
o.gLat / o.gLonG横向 / 纵向加速度，可判断对手是否吃满抓地。

刹车灯也用了这份数据：inBrake > 0 时尾灯点亮，所以线上对手踩刹车你能直接看见红光。

三条使用约定

  • 只含未完赛车：已冲线的车会被幽灵化并从数组里移除，所以不用判断 o.finished。
  • 含车辆状态与踏板输入，但不含算法内部状态：你拿不到对手的前瞻点、目标速度等，只能从速度/朝向/踏板推测意图。
  • 顺序不固定：按车辆创建顺序排列（单机即发车位顺序），不要依赖下标含义，判断身份请用对象引用比较（o === car）。

在线对战的精度说明

在线房间里，你自己的车在本地模拟（数据实时且精确）；其他玩家的车来自服务器快照插值（位置/朝向约 30Hz 插值， 踏板输入按其 12Hz 上报中继），做贴身超车判断时建议留 1~2m 余量。AI 补位车由服务器 30Hz 模拟，精度更高。

示例：找最近的前车并跟车

function driver(car, out, dt, otherCars) {
  let lead = null, leadGap = Infinity;

  for (const o of otherCars) {
    if (o === car) continue;                       // 数组包含自己，先排除
    const geo = getCarDistance(car, o);            // 统一航向坐标系下的相对位置
    if (geo.sLon <= 0) continue;                   // sLon > 0 才说明对方在前方
    if (geo.gapLateral > 1.8) continue;            // 横向错开超过一个车身，不算同车道
    if (geo.sLon < leadGap) { lead = o; leadGap = geo.sLon; }
  }

  if (lead && leadGap < 12) {
    out.up = false;                                // 距离太近，松油门
    if (leadGap < 7 && lead.speed < car.speed) out.brake = 1;
  } else {
    out.up = true;
    out.brake = 0;
  }
  // 方向照常跟赛车线
  const j = (car.nearIdx + 3) % N;
  out.steer = clamp(wrapAngle(Math.atan2(lineY[j] - car.y, lineX[j] - car.x) - car.angle) * 1.6, -1, 1);
}

也可以用现成的 evaluateTrafficAndOvertake(car, otherCars, car.nearIdx, dt)， 它内部已经处理了"排除自己 + 选前车 + 变线超车"，返回目标点和限速建议。

示例：看到前车刹车灯就提前收油

function driver(car, out, dt, otherCars) {
  let closing = false;
  for (const o of otherCars) {
    if (o === car) continue;
    const geo = getCarDistance(car, o);
    const ahead = geo.sLon > 0 && geo.sLon < 25;   // 正前方 25m 内
    const sameLane = geo.gapLateral < 1.6;          // 横向不足一个车身
    if (ahead && sameLane && (o.inBrake > 0 || o.speed < car.speed - 8)) closing = true;
  }

  out.up = !closing;                 // 前车在刹车 / 明显比我慢 → 先松油
  out.brake = closing && car.speed > 40 ? 1 : 0;
  out.steer = 0;                     // 方向另算
}

车身尺寸与间距：怎么判断"能不能过"

每辆车按 5.6m × 2.0m 的矩形包围盒处理（CAR_LENGTH = 5.6、CAR_WIDTH = 2.0）： 车头在中心 +2.8m、车尾 -2.8m，左右各 1.0m。 跟车 / 并排 / 变线的判断全部基于这个盒子，不需要自己再猜车长。

getCarDistance(a, b) 的返回值

字段含义怎么用
sLon纵向距离（米），在两车平均航向上测得> 0 表示 b 在 a 前方；< 0 表示在后面
dLat横向偏移（米），垂直于平均航向正负表示对方在左 / 右，绝对值看偏离多少
gapFrontRear车头车尾净空隙 = |sLon| - 5.6> 0：前后完全错开；< 0：纵向重叠
gapLateral车侧净空隙 = |dLat| - 2.0> 0：横向错开（并排也不碰）；< 0：横向重叠
distCenter两车中心直线距离粗略排序"谁离我最近"

判定规则

前后跟车：gapFrontRear > 0 才算真正错开

  A  [======>]
                        gapFrontRear = |sLon| - 5.6
            [======>]  B

并排行驶：gapLateral > 0 才不会碰到

  A  [======>]
  B  [======>]          gapLateral = |dLat| - 2.0

两个净空隙同时 < 0  →  包围盒重叠 = 接触（物理会分离 + 后车掉速）
const geo = getCarDistance(car, o);

if (geo.gapFrontRear > 0) { /* 前后错开：可以放心变线 */ }
if (geo.gapLateral > 0) { /* 横向错开：不算同车道，不用跟车 */ }
if (geo.gapFrontRear < 0 && geo.gapLateral < 0) { /* 已经贴上，赶紧减速/让线 */ }

建议的安全余量

场景建议阈值
跟车（开始全力追）gapFrontRear > 8 ~ 12m
并排超车（可以贴上去）gapLateral > 0.8m
变线完成横向移动约 2.0m（一个车宽）+ 0.5m 余量
判断正前方同车道sLon > 0 && gapLateral < 0（横向重叠才算正前方）

注意：sLon / dLat 用的是"两车平均航向"坐标系，交换 a / b 时符号严格取反（追尾判定不依赖调用顺序）。 但当两车夹角很大（超过约 60°，例如一方打滑横在赛道上）时会退回到 a 的航向，此时"前后 / 左右"的划分会变模糊，建议改用 distCenter 做粗略避让。

4. 可以写入：out（控制输出）

字段类型作用
out.steer 可写-1 ~ 1方向盘。负 = 左，正 = 右。转向需要速度：0→3 m/s 线性生效，静止打不了方向。
out.up 可写bool油门。只有在 brake === 0 时才生效。
out.brake 可写0 / 1 / 20 松开、1 轻刹（45% 制动力）、2 重刹（100%）。刹车优先级高于油门。
out.left / out.rightbool旧式方向键模拟。只在你把 out.steer 写成非数字时才生效，建议直接用 out.steer。
out.targetX / out.targetY / out.targetSpeed数字只用于「AI 探测线」可视化（视图工具面板里打开开关），不影响物理。注意单人模式下不绘制，对战 AI / 观战 / 在线对战才看得到。

约定：out.up 按真值判断（写 1 / "x" 也算踩油门）； out.brake 必须是数字：只有严格等于 2 才是重刹，其它任何正数（含 1、1.5、3）都按轻刹 45% 处理，0 / 负数 / 不写 = 松开； out.steer 会被钳到 -1~1。

5. 可以读取：赛道数据（自动注入）

名称含义
N中心线采样点数量。pts/nor/hw/curvS 的下标范围 0 ~ N-1（环形赛道需取模）。
pts[i]{x, y} 中心线第 i 个点（米）。
nor[i]{x, y} 该点单位法向（指向行进方向右侧）。横向偏移 = pts[i] + nor[i] × off。
hw[i]该点赛道半宽（米）。路面内 0 ~ hw，外侧是路肩 / 草地。
curvS[i]平滑后的有符号曲率（1/m）。|curvS| > 1/110 基本就是弯道；半径 = 1/|curvS|。
lineX[i] / lineY[i]预计算的最优赛车线（在赛道内侧，离路缘约 3.4m）。跟这条线通常最快。
DS中心线采样间距（米），把「米」换算成「下标」时用：idx + 距离 / DS。
PHYS全局物理常量：brake(61.6)、lightBrakeFactor(0.45)、latGrip、maxOmega、maxSpeed、accelCurve 等。
CAR_LENGTH / CAR_WIDTH车身包围盒 5.6m × 2.0m（车头车尾各 2.8m、左右各 1.0m），详见 车距与车身尺寸。

track：赛道元信息

字段说明
track.id / track.name / track.flag当前赛道 id、中文名、国旗。
track.length本场计算的圈长（米）。直线冲刺赛道是 6km 计赛长度。
track.turns弯道数量。
track.laps本场圈数（跟随菜单 / 房间设置）。
track.isLinear是否直线冲刺赛道（起点→终点不闭合）。
track.N / track.DS / track.HW采样点数 / 采样间距（米）/ 基础半宽（米）。
track.kerbFlag[i]1 = 该采样点铺了红白路缘石（可以放心压）。
track.idxAt(米)沿赛道距离 → 采样下标；环形赛道自动取模，直线赛道自动钳制。

track 的每个字段都是实时读取的：换赛道后自动变成新赛道的数据，不需要重新编译算法。 例如 const j = track.idxAt(car.trackS + 30); 直接拿到 30 米后的采样点。

没有注入、别写错名字的东西

你可能会想写正确写法
isLineartrack.isLinear
HW / LAP_LENGTHtrack.HW / track.length（每条赛道不同）
rcurvS（未平滑原始曲率）、vTarget（AI 目标速度表）不注入；曲率统一用 curvS，弯速用两张 *Cap 表
import / require / 访问其他模块不支持。代码是 new Function 编译的纯函数体，只能用它注入的标识符 + Math / console 等浏览器全局

环形赛道 vs 直线冲刺

  • N、DS 每条赛道都不一样，不要把下标写成常数、也不要把"米"直接当下标用。
  • 环形：前进 step 个采样点写 (i + step) % N（负数要先 +N 再取模）。
  • 直线冲刺：赛道不闭合，必须 Math.min(i + step, N - 1) 或 track.idxAt(米)； 照环形写 % N 会让"前方"绕回起点，前车/弯道判断直接错乱。

6. 可直接调用的工具函数

函数说明
clamp(v, a, b)把 v 限制在 [a, b]。
wrapAngle(a)把角度差归一化到 (-π, π]，算航向误差必用。
getSuperCornerCap(perf)返回每个采样点的弯中极限速度表（Float32Array，单位 m/s，96% 抓地利用率，±30m 对称窗口）。直接查表当目标速度。
getApexReleaseCap(perf)内置 geminiDriver 在用的「过弯心即释放」弯速表：非对称窗口 −2m ~ +10.5m、孤立弯出弯允许外抛走线（等效曲率 ×0.86）、抓地利用率 96.5%。出弯约 10m 就解除限速，比上面那张表更快。
evaluateTrafficAndOvertake(car, otherCars, ti, dt)内置跟车 / 超车决策。返回 { targetX, targetY, shouldSlow, speedCap, steerBias, emergencyBrake, isOvertaking }。
getCarDistance(a, b)返回 { sLon, dLat, gapFrontRear, gapLateral, distCenter }。sLon > 0 表示 b 在 a 前方；gap 为净空隙（负值 = 包围盒重叠）。
superDriver(car, out, dt, otherCars)游戏内置的完整算法（双前瞻 + 时间最优刹车规划 + 超车状态机）。可以直接调用，或者先调用它再覆盖个别 out 字段。

两张弯速表怎么选： getSuperCornerCap 用前后各 30m 的对称窗口，弯后 30m 内仍会被弯心限速压着，偏保守； getApexReleaseCap 是 geminiDriver 在用的非对称窗口（只看身后 2m、身前 10.5m），过弯心约 10m 后就允许加速， 且识别到孤立弯时会按外抛走线把等效曲率打 0.86 折，出弯更快。想追极限用后者，想稳一点用前者。 两个函数都按 perf + 当前赛道做缓存，每帧调用没有额外开销。

6.1 getApexReleaseCap(perf) 是什么

它不是 car 或 out 上的字段，也不是参数，而是系统注入到你算法作用域里的一个查询函数： 传入一份车辆性能配置，返回这辆车在当前赛道上每个采样点的极限过弯速度表。 内置算法 geminiDriver / superDriver 的纵向控速就是查这张表。 

const cap = getApexReleaseCap(car.perf);   // Float32Array，长度 = N，单位 m/s（×3.6 = km/h）
const j   = (car.nearIdx + Math.round(30 / DS)) % N;
const vLimit = cap[j];                     // 前方 30m 处最多能跑多快
if (Math.abs(car.speed) > vLimit) out.brake = 1;

它回答的是什么问题

只回答「这一个采样点，最多能用多快的速度通过」——不考虑交通、不考虑你现在在哪。 交通 / 超车 / 走线偏移请用 evaluateTrafficAndOvertake(...) 和 lineX / lineY。 它本质上就是一张长度为 N 的只读速度表，查表是 O(1)。

名字里的 "Apex Release"（过弯心即释放）

项getSuperCornerCapgetApexReleaseCap
观察窗口前后各 30m（对称）身后 2m / 身前 10.5m（非对称）
出弯表现过弯心后仍被弯心限速压约 30m，保守过弯心约 10m 后即解除限速，可提前加油
孤立弯出弯无额外处理判定为非连续弯，等效曲率 ×0.86（外抛走线放大半径）
抓地利用率96%96.5%（更贴近极限）
使用方固定 30m 窗口的通用弯速内置 geminiDriver 实际在用的表

每点的值 = min(沥青极速, √(A_LAT × R), maxOmega / k)， 其中 k 是该点附近窗口内的最大曲率，R = 1/k， A_LAT = latGrip × min(1, 0.965 × cornerGripMult)。连续 S 弯不做 0.86 折损。

三条使用约定

  • 按 perf 对象 + 当前赛道双键缓存：每帧调用没有额外开销，换赛道后自动失效重建，不用手动清。
  • 返回的是共享缓存数组，只读：不要写 cap[i] = ...，所有用同一份 perf 的车（含 AI）共用这张表，改了会污染别人。
  • 必须传真实的性能对象：getApexReleaseCap(car.perf)；手工拼一个假对象会得到错误限速（缺字段时回落到 PHYS 默认值）。

最小用法：纯追踪 + 这张表控速

function driver(car, out, dt) {
  const v = Math.abs(car.speed);
  const i = car.nearIdx % N;

  // 方向：朝赛车线前瞻点打
  const j = (i + Math.round((12 + v * 0.55) / DS)) % N;
  const err = wrapAngle(Math.atan2(lineY[j] - car.y, lineX[j] - car.x) - car.angle);
  out.steer = clamp(err * 1.8, -1, 1);

  // 纵向：查表，超速就刹
  const cap = getApexReleaseCap(car.perf);
  const vLimit = cap[j];
  out.brake = v > vLimit + 6 ? 2 : v > vLimit + 1 ? 1 : 0;
  out.up = out.brake === 0 && v < vLimit;
}

6.2 evaluateTrafficAndOvertake(car, otherCars, ti, dt) 返回值

字段类型 / 单位怎么用
targetX / targetY米已经叠加了超车侧移的推荐目标点，可以直接当纯追踪的瞄准点。
shouldSlowbool是否应跟车降速（同车道前车太近）。为 false 时别用 speedCap。
speedCapm/s跟车限速（约等于前车速度 ×0.97）；无阻挡时为 Infinity。
steerBias-0.14 ~ 0.14并排时的防挤碰方向偏置，直接加到你的 out.steer 上。
emergencyBrakebool贴到前车了，立刻 out.brake = 2。
isOvertakingbool当前侧向偏移已超过 0.6m（正在抽头/变线），可用来切换策略。
 
const v  = Math.abs(car.speed);
const ti = (car.nearIdx + Math.round((16 + v * 0.5) / DS)) % N;   // 前瞻下标必须合法
const tr = evaluateTrafficAndOvertake(car, otherCars, ti, dt);

out.brake = tr.emergencyBrake ? 2 : (tr.shouldSlow && v > tr.speedCap ? 1 : 0);
const err = wrapAngle(Math.atan2(tr.targetY - car.y, tr.targetX - car.x) - car.angle);
out.steer = clamp(err * 1.8 + tr.steerBias, -1, 1);
out.up    = out.brake === 0;

有状态：这个函数会读写 car._latOffset 来平滑侧移，所以每帧只调用一次（不要在同一帧里对多个前瞻下标各调一次， 也不要在内置 superDriver 之后再调用它，两者会抢同一个偏移量）。ti 越界会读到 undefined 并算出 NaN。

7. 坐标系与单位

  • 世界单位：1 = 1 米，速度 m/s，加速度 m/s²，角度弧度。
  • x 向右、y 向下（屏幕坐标），所以 angle 增大 = 屏幕上顺时针。
  • 侧向偏移约定：pts[i] + nor[i] × off，off > 0 在中心线右侧（相对行进方向）。
  • 超出路面：|off| < hw 沥青；hw ~ hw+1.5 有路缘石的弯才是路肩；再往外是草地（极速与加速都会骤降）。

8. 物理边界（写这些值不会突破）

  • 满刹减速度 = PHYS.brake × perf.brakeMult（默认约 61.6 m/s² ≈ 6.3g），轻刹为其 45%。
  • 转向角速度 ω = min(maxOmega, 可用横向抓地 / v) × min(1, v/3)；刹车会占用摩擦圆，重刹时可用横向抓地会下降到约 77%。
  • out.brake > 0 时 out.up 无效；倒车需要用 brake = 2 停稳后继续按住。
  • 草地会大幅降低极速、加速，并削弱转向（×0.74）。

9. 最小可用示例（纯追踪 + 弯速限速）

// 沿内置赛车线走：近点控方向，弯速表控油门/刹车
function driver(car, out, dt) {
  const N_ = N;                                  // 采样点数量
  const i = car.nearIdx;
  const v = Math.abs(car.speed);

  // 1) 前瞻点：速度越快看得越远
  const look = 12 + v * 0.55;                    // 米
  const step = Math.round(look / DS);
  const j = (i + step) % N_;                     // 环形赛道取模；直线冲刺赛道用 Math.min(i+step, N_-1)

  // 2) 转向：朝赛车线打方向
  const dx = lineX[j] - car.x;
  const dy = lineY[j] - car.y;
  const err = wrapAngle(Math.atan2(dy, dx) - car.angle);
  out.steer = clamp(err * 1.8, -1, 1);

  // 3) 纵向：查弯速表，超了就刹
  const cap = getSuperCornerCap(car.perf)[j];    // m/s
  if (v > cap + 6) out.brake = 2;
  else if (v > cap + 1) out.brake = 1;
  else out.brake = 0;

  out.up = out.brake === 0 && v < cap;
}

10. 注意事项

  • 调用频率：每个物理子步一次（正常约 60 次/秒）。按 + / - 开倍速快进时同一帧会切多个子步 （最多 32 步/帧），调用次数同步放大，因此不要在函数里做重循环、大数组分配或 console.log。
  • 状态保存在 car 上：内置算法用 car._cruiseStuck 之类的字段存记忆；你自己的算法也可以挂 car._myState 这类字段，换车/重开时新车辆对象会自然重置。
  • 不要再读 keyboard input：开启自动驾驶后键盘输入完全不生效，你的车只认 out（car.inUp / car.inBrake 反映的就是你自己上一帧写出去的值）。
  • 在线对战：算法在你本地运行，驱动力由你的客户端上报；服务器仍会按赛道最短圈做成绩合理性校验。
  • 切换赛道：lineX / pts / getSuperCornerCap 等会在换赛道后重建，系统会自动用新数据重新编译你的代码， 不需要重开页面。注意重编译等于重新执行整段代码，写在顶层的 let / const 状态会被重置。
  • 开关入口：选车面板或在线房间里的「🤖 自动驾驶」按钮；开/关状态会记在浏览器里。比赛中途切换立即生效 （关闭时交还键盘控制，不重开赛）。
  • 调试手段：console.log 可用；把前瞻点写进 out.targetX/targetY 并在视图工具里打开「AI 探测线」， 能直接在赛道上看到你的瞄准点（单人模式不绘制）；浏览器控制台里还有 window.__gp 调试入口 （__gp.cars / __gp.race 等，属于内部接口，可能随版本变动）。
